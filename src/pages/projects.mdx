## ask-my-docs

<p className="proof-labels"><ProofLabel>56 tests · CI · Recall@4 10/10</ProofLabel></p>

Ask questions about a folder of Markdown documentation and get answers from Claude, with sources.
It's a small example of **retrieval-augmented generation (RAG)**: instead of asking a model to answer
from memory, it first finds the relevant parts of your documents and gives the model only those.

**Repository:** [github.com/kopyk/ask-my-docs](https://github.com/kopyk/ask-my-docs)  
**Built with:** Python 3.10+, the Anthropic Python SDK, pytest, GitHub Actions, and the MCP Python SDK  
**Tutorial:** [Build a Q&A bot over your docs](/docs/ai/rag-tutorial) walks through a simplified version.

```bash
python ask.py path/to/docs "Your question here"
```

Each claim on the label above is backed by something in the repository that you can run.

| MCP server | `mcp_server.py` exposes retrieval as a `search_docs(question, top_k)` tool for Claude Code and Claude Desktop. It is tested through the SDK's client both in memory and over stdio as a subprocess. |
| Changelog | `CHANGELOG.md` follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); its versions and dates come from the commit history, not from memory. |

### How it works

1. **Load.** `load_sections()` reads every `.md` file and splits it into sections at each heading.
2. **Retrieve.** `find_relevant()` scores each section by which of the question's words it contains,
   ignoring common words. Rare words count more: each word gets the weight log(N / df), where N is the
   number of sections and df is how many sections contain the word. The tool keeps the top 4 sections.
3. **Generate.** `ask_claude()` sends those sections and the question to Claude. The system prompt tells
   Claude to answer only from the sections, say so when they don't cover the question, and list its sources.

### Retrieval evaluation

`evaluate.py` checks whether retrieval finds the right file for 10 test questions, each paired with the
file that holds its answer. It reports **recall@k**: the share of questions whose answer file was among
the top k sections retrieved. `--compare` runs three scorers side by side.

| Scorer | How it scores a section | Recall@2 | Recall@4 | Recall@8 |
|--------|-------------------------|----------|----------|----------|
| count | How many times question words appear (favors long sections) | 9/10 | 10/10 | 10/10 |
| share | Share of question words the section contains | 9/10 | 9/10 | 9/10 |
| weighted | Like share, but rare words count more (default) | 9/10 | 10/10 | 10/10 |

Ten questions is a small sample, so treat the score as a rough check. The evaluation doesn't call Claude,
so it runs without an API key.

### Limitations

- **Keyword matching only.** A question about "attacking early" won't find a section that only says
  "invade." Embeddings, which match by meaning, are the next step.
- **Markdown only.** PDFs and other formats aren't read.

## Gainwell Technologies: DC Medicaid EDI companion guides

**Role:** Technical Writer Intern, Gainwell Technologies · May–Aug 2025 · Irving, TX

A case study from the internship. The guides are HIPAA EDI companion guides that Gainwell publishes for
DC Medicaid trading partners; the two I worked on are linked at the end.

### Problem

The Washington, D.C. EDI team's companion guides had to be written and revised under aggressive
deadlines, consolidating contributions from 20+ subject-matter experts while maintaining HIPAA and
ASC X12 compliance. Vendor onboarding questions were the measure of whether the guides were doing
their job.

### What I did

- Wrote the 837I v1.3 update and edited and enhanced the 276/277 v1.1 guide.
- Wrote and revised 6 companion guides for the Washington, D.C. EDI team in total.
- Contributed to an 80-page Project Management Plan and Software Design Document.
- Consolidated 20+ SME contributions into final deliverables under aggressive deadlines while
  maintaining HIPAA and ASC X12 compliance.
- Designed and presented an interactive Power BI vendor-tracking dashboard to 15+ stakeholders.
- Reformatted the 276/277 guide into a cited, scannable Markdown version.

### Outcome

- Vendor onboarding questions fell by about 30%.
- The Project Management Plan and Software Design Document became the team's permanent SOP for EDI
  workflows.
- The Power BI dashboard was adopted for ongoing project monitoring.
- The 837I v1.3 and 276/277 v1.1 guides are published on Gainwell's site.

## Jungle Decision Framework

A personal documentation project: a decision-making framework for jungling in League of Legends,
written as a documentation site rather than a guide. It covers macro play, tempo and information
instead of champion mechanics, and it is organized so a reader can start with simple, repeatable
actions and scale up: foundations, decision rules, a decision tree, worked examples, common
mistakes, and a glossary.

**Site:** [docs.jordanyan.com](https://docs.jordanyan.com) (built with Docusaurus)

It also serves as the test corpus for ask-my-docs: the 10 evaluation questions were written against a
frozen snapshot of that site's docs folder, so the Recall@4 result above is measured on documentation
I wrote.
